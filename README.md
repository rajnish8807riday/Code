Depression Detection in Low-Resource Languages: A BERT-Based Deep Learning Approach for Hindi and Bhojpuri Social Media Posts
=====================================================================

Overview
--------
--------
This repository contains Jupyter notebooks for experimenting with neural-network
models for binary text classification on Hindi and Bhojpuri text datasets. The
notebooks load text and labels, preprocess the text, train models, and evaluate
their predictions.

The main model families represented in the notebooks are:
- Multilingual BERT
- Convolutional Neural Network (CNN)
- LSTM and Bidirectional LSTM (BiLSTM)
- LSTM with an attention mechanism
- BERT combined with CNN layers
- BERT combined with LSTM and attention

The Hindi notebooks use `Hindi_Depression.csv`. The Bhojpuri notebooks use
`merged_data.csv`. The code treats the task as supervised classification using
text and label columns. Check the dataset documentation and label mapping before
interpreting a predicted class as a particular outcome.

How the Notebooks Work
----------------------

1. Load the dataset
   The notebooks read CSV files into pandas DataFrames. The usual fields are
   `text` (the input sentence/document) and `label` (the target class). Some
   Bhojpuri hybrid-model code reads the CSV with explicit column names, so make
   sure the file's actual column order matches that code.

2. Split the data
   The code uses `train_test_split` to divide data into training and evaluation
   subsets, often with `random_state=42`. Some BERT notebooks call the
   validation split `dev`. Review each notebook's split logic before treating
   its reported scores as a final held-out test result.

3. Convert text into model inputs
   - BERT notebooks use the Hugging Face tokenizer for
     `bert-base-multilingual-uncased`, generally padding/truncating sequences to
     a maximum length of 128 tokens.
   - CNN/LSTM notebooks use Keras tokenization and padded integer sequences.
     These notebooks construct an embedding matrix from 100-dimensional
     GloVe Twitter vectors when the vector file is available.

4. Build and train models
   - BERT: obtains contextual token representations from a pretrained
     multilingual Transformer and adds a classification head.
   - CNN: applies one-dimensional convolutional filters to token embeddings to
     detect local text patterns.
   - LSTM: processes token sequences recurrently.
   - BiLSTM: processes sequences in both directions.
   - Attention: computes weights over sequence representations so the model can
     combine information from different token positions.
   - BERT-CNN: applies convolutional branches with different kernel sizes to
     BERT's token representations.
   - BERT-LSTM: combines contextual BERT representations with recurrent
     processing and attention.

5. Evaluate predictions
   The notebooks report metrics such as accuracy and a classification report
   (precision, recall, F1-score, and support). Some hybrid notebooks also
   include code for confusion matrices, ROC curves, AUC, or precision-recall
   curves. Use the outputs generated by your own run; this README does not claim
   a particular model is more accurate than another.

Requirements
------------
The notebooks primarily use Python with:
- pandas
- NumPy
- scikit-learn
- TensorFlow / Keras
- Hugging Face Transformers
- matplotlib (for plots)

The BERT notebooks include a Transformers version pin in some cells
(`transformers==4.37.2`). The CNN/LSTM notebooks also depend on a local GloVe
Twitter embedding text file. Compatible package versions may need to be selected
for your Python and TensorFlow environment.

Execution Environment: Google Colab
------------------------------------
These experiments were developed and run in **Google Colab**, rather than a
local Jupyter Notebook environment. Google Colab provides hosted notebook
execution and access to accelerator runtimes, including TPUs when available.
The TPU runtime was the reason for choosing Colab for these experiments.

To run the notebooks:

1. Upload or open the relevant `.ipynb` file in Google Colab.
2. In Colab, open **Runtime → Change runtime type** and select a TPU accelerator
   if it is available for your account and runtime.
3. Run the notebook cells in order. Execute any package-installation cells before
   importing the relevant libraries.
4. Make the datasets and embedding files accessible to the Colab session, for
   example by mounting Google Drive or uploading the files.
5. Update any file paths so that they match the location of your data in the
   current Colab session.

The notebooks include TensorFlow distribution/TPU setup code in some places.
TPU use depends on the runtime configuration and the code's compatibility with
the selected accelerator. If TPU initialization is unavailable or fails, review
the notebook's fallback code and select another supported runtime.

Package versions should be kept compatible with the Python version and Colab
runtime. Some BERT notebooks pin `transformers==4.37.2`; follow the installation
cells in each notebook where present. The notebooks use pandas, NumPy,
scikit-learn, TensorFlow/Keras, Hugging Face Transformers, and matplotlib.

Important implementation notes
------------------------------
- These are research notebooks designed for execution in Google Colab, not a
  packaged command-line application or ready-to-deploy API.
- Several notebooks use hard-coded Google Drive paths and must be configured
  before execution.
- Some notebooks use GloVe vectors stored at a personal Drive path.
- A few hybrid notebooks contain extra experimental code beyond the main model
  demonstrated by the notebook name. Review and run those cells separately.
- Check the train/validation/test split and the labels used for evaluation.
  Some cells create a `test` subset but later evaluate predictions against the
  broader `dev` subset; verify alignment before relying on reported metrics.
- Confirm that the output layer, loss function, label encoding, and prediction
  threshold/argmax are consistent with the dataset's number of classes.
- Results can vary with package versions, random initialization, hardware, and
  dataset preprocessing. Re-run experiments before reporting results.
- The code uses the term “depression” in the Hindi dataset filename. The exact
  meaning of each class must be taken from the dataset's own label definition;
  model outputs should not be treated as clinical diagnoses.

Reproducibility and responsible use
-----------------------------------
For reproducible experiments, document the dataset version, preprocessing,
random seed, package versions, training configuration, and evaluation split.
Avoid comparing metrics from different splits as if they were measured on the
same test set. If this work is used in a paper or project, report limitations,
class-wise results, and any preprocessing or label decisions.
